## 1. 최종 구조 요약

```
[퍼즐룸 — 규칙형 문 / 순서형]
FPuzzleDoorRule (USTRUCT, 신규)
    RuleName / RequiredSensors / DoorsToOpen / bRequirePreviousRule / bCompleted(런타임)
APuzzleRoomVolume
    DoorRules(배열) 추가 — 기존 Sensors + ExitDoors(AND형)는 그대로 유지, 둘 다 같이 사용 가능
    CanSensorActivate() — 순서형에서 차례가 아닌 센서 차단
    ContainsSensor() — Sensors/규칙 어디든 포함 여부
    IsPuzzleSolved() — 사용하는 방식(AND/규칙) 전부 완료 시 true
    BeginPlay — Sensors + 규칙 센서 전부 OwningRoom 자동 연결, 규칙 설정 검증 로그
    ResetRoom — 센서 끄기 + 완료 규칙의 문 닫기 + 규칙 상태 초기화 (클리어한 방은 생략)
    RuleCompleteSound(신규) / ClearSound(전체 클리어 시 1회)
APuzzleSensorActor — NotifyHitByLight에서 CanSensorActivate 검사
APuzzleResetActor — 표시 조건을 IsPuzzleSolved()로 변경

[사거리]
AMirrorActor
    ReflectedRangeMultiplier (기본 2) — 반사 후 "무기 기본 사거리 × 배율"로 사거리 재충전
AProjectile
    BaseMaxRange(발사 시점 사거리) — 거울 반사 시 MaxRange = BaseMaxRange × 거울 배율
    ScaleMaxRange() — 방 배율 적용용
ULumenCombatLibrary::FireReflectiveLineTrace
    RangeMultiplier 인자(기본 1), 거울 반사 시 MaxTraceRange × 거울 배율
ARoomVolume
    PlayerRangeMultiplier (기본 1) — 방 안에서 플레이어 사거리/조준선 배율 (현재 모든 방 1)
ALumenCharacter
    SetCurrentRoom()을 cpp로 이동 + ApplyRoomRangeMultiplier() — 발사체/초록/조준선에 배율 전달
ULumenAimLineComponent::SetRangeMultiplier() — 조준선 길이 = 실제 사거리 유지
```

## 2. 구현/수정된 기능

### 2-1. 퍼즐룸 규칙형 문 (특정 센서 → 특정 문)
- 규칙 하나 = "이 센서들이 **전부** 켜지면 → 이 문들을 연다"
- 센서 1개 → 문 1개, 여러 센서 조합 → 비밀문 등 자유롭게 구성
- 문 여는 책임은 계속 방(PuzzleRoomVolume)에 있음 — 7주차에 정한 원칙 유지
- 기존 AND형(Sensors + ExitDoors) 배치는 수정 없이 그대로 동작

### 2-2. 순서형 센서 (논의 정리 8장)
- 규칙의 `bRequirePreviousRule` 체크 → 앞 규칙 완료 전에는 이 규칙의 센서가 빛에 맞아도 켜지지 않음
- 예: [0] 빨강→문1 / [1] 파랑→문2(체크) / [2] 초록→출구(체크) = 단계별 리빌
- 원래 설계(`FPuzzleStage` + `CurrentStageIndex`)를 별도 방 타입으로 만들지 않고, 규칙 구조에 옵션 하나로 통합
- 사망 시 진행 전체 초기화 (센서 꺼짐, 완료 규칙의 문 닫힘, 1단계부터)

### 2-3. 거울 반사 시 사거리 증가
- 처음 발사 사거리는 무기 DA 그대로 (전투 밸런스 유지)
- 맵 거울 반사 → 그 지점부터 **무기 기본 사거리 × 거울 배율**만큼 새로 날아감 (기본 2배)
- 여러 거울을 거쳐도 누적 곱셈 없음 — 매번 기본 사거리 기준 재계산 → 퍼즐 거리 예측 가능
- 방패 반사는 기존대로 남은 거리 누적 유지
- 발사체/초록/퍼즐 광원(`ALightEmitterActor`) 빛 모두 적용, 거울마다 배율 다르게 설정 가능

### 2-4. 방별 사거리 배율 (기능만 유지, 현재 미사용)
- 처음엔 "퍼즐룸 안에서 사거리 3배"로 구현했으나, 기존 사거리를 유지하자는 결정으로 퍼즐룸 기본값을 1로 되돌림
- 기능은 남겨둠: 방 Details `Room | Range → Player Range Multiplier`로 특정 방만 사거리 확장 가능
- 적/광원에는 적용 안 됨, 조준선 길이도 같이 바뀌어 실제 사거리와 일치

### 2-5. 공격 예고음 생성 프롬프트
- ① Charge(텔레그래프 채움 구간, 색별) + ② Cue(발사 직전, 공통 1개)로 분리
- 빨강=중음역 짧게 / 파랑=저음 넓게 / 초록=고음 조여드는 — 화면 밖 공격도 소리로 구분 (접근성)
- 톤: 미스터리·애수, 고대 크리스털 빛 기술. 잔향 최소(다중 텔레그래프 겹침 대비)
- 재생 코드(DA에 `TelegraphChargeSound`/`TelegraphCueSound`)는 사운드 파일 준비 후 작업 예정

## 3. 겪었던 문제와 해결 과정 (트러블슈팅 기록)

| 문제 | 원인 | 해결 |
|---|---|---|
| 빌드 후에도 퍼즐룸 Details에 `Door Rules`가 안 보임 | 프로젝트의 실제 파일에 규칙 코드가 들어가 있지 않았음. 프로젝트는 그사이 폴더 정리(`Level/`, `Combat/`, `Reflection/`) + 사운드 필드 추가 등으로 채팅에서 주고받던 버전과 달라져 있었음 | 프로젝트 폴더를 연결해 실제 파일을 기준으로 규칙 기능만 병합. 사운드(`ClearSound`/`ActivateSound`/`WrongColorSound`/`ResetSound`)와 주석·include 경로 보존 |
| (예방) `TArray<TObjectPtr<T>>::Contains(const T*)` 비교 | 컴파일러/엔진 버전에 따라 const 포인터 비교가 실패할 수 있음 | `ArrayHasSensor()` 헬퍼로 `Elem.Get() == Sensor` 직접 비교 |
| 퍼즐 배치 시 사거리가 너무 짧음 | 원킬 밸런스용 짧은 Max Range가 퍼즐에도 그대로 적용 | 1차: 방별 사거리 배율(퍼즐룸 3배) → 결정 변경으로 기본 1 복귀 → 최종: 거울 반사 시 사거리 배율 |

## 4. 현재 알고 있는 한계

- **빌드/테스트 미확인**: Door Rules, 순서형, 거울 반사 사거리 배율 — 에디터 닫고 빌드 후 확인 필요
- **순서형 잠금 표시 없음**: 차례가 아닌 센서와 아직 안 켠 센서가 겉보기에 같음 → 테스트에서 헷갈리면 잠긴 센서를 어둡게 표시
- **조준선은 첫 구간만 표시**: 거울 반사 후 늘어난 사거리는 조준선에 보이지 않음 (반사 경로 미리보기는 별도 기능)
- **이전 채팅 버전과 프로젝트 차이**: `LumenCharacter`(낙사 리셋/프롬프트 보강) 등 이전에 채팅으로 준 파일이 프로젝트에 어떻게 반영됐는지는 이번 작업 범위(사거리 관련 부분) 외엔 전수 확인 안 함
- **공격 예고음**: 프롬프트만 작성, 사운드 파일·재생 코드 미작업
- 이전 문서의 한계 항목(문이 위로 열림, 발열 게이지 디버그 표시 등)은 그대로 유지
